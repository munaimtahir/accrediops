# Baseline and Scope - Complete CAPA UI Exposure & Workflow Usability Sprint

## Current Status
- The core workflow is complete and pilot-ready.
- Evidence bridge is stable.
- CAPA backend model implemented.
- CAPA lifecycle operational.
- CAPA APIs complete.
- Readiness/export integration includes CAPA.
- Final ZIP export works.
- Recurring workflow stabilized.

Current gap: CAPA exists, but all CAPA features must be exposed clearly in the frontend so users can actually use the full Gap/CAPA workflow.

## Scope
The UI must allow users to:
1. View all gaps.
2. Create a gap from a missing/partial/rejected evidence requirement.
3. View all CAPA records.
4. Create CAPA from a gap.
5. Assign responsible person and due date.
6. Update CAPA progress.
7. Link closure evidence.
8. Submit CAPA for review.
9. Close CAPA as reviewer/approver.
10. Reject CAPA with reason.
11. See CAPA blockers on readiness screen.
12. See CAPA report in print-pack/export screen.
13. Understand which CAPA blocks final ZIP export.

## Out of Scope
- Rebuilding backend CAPA models.
- Redesigning the whole frontend.
- Changing production routing or unrelated services.
