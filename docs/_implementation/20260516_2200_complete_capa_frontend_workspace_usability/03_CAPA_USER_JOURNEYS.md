# CAPA User Journeys

## Journey 1: Missing evidence to CAPA
1. User navigates to **Indicator detail**.
2. User identifies a missing evidence requirement.
3. User clicks **Record Gap**.
4. The system opens the **Create Gap Modal**. The user fills in details and saves.
5. User clicks **Initialize CAPA** from the new Gap.
6. The system opens the **Create CAPA Modal**. The user assigns a responsible person, due date, and saves.
7. The CAPA owner updates the CAPA plan, links closure evidence, and clicks **Submit for review**.
8. A reviewer reviews the CAPA and clicks **Close CAPA**.
9. The Readiness screen is updated to reflect the removed blocker.

## Journey 2: Rejected evidence to CAPA
1. Reviewer rejects evidence.
2. The user sees a visible Gap on the Indicator Detail screen.
3. The user creates a CAPA from the Gap, adding a corrective action.
4. The user links new closure evidence and submits the CAPA.
5. The reviewer closes or rejects the CAPA based on the new evidence.

## Journey 3: Management review
1. A Lead opens the **Gap & CAPA Dashboard**.
2. The Lead filters for high-risk CAPA or opens the overdue CAPA list.
3. The Lead views the linked indicator for context.
4. The Lead checks the export blockers list to ensure readiness isn't impeded by delayed CAPAs.

## Journey 4: My tasks
1. An Owner opens the **My CAPA Tasks** tab.
2. The Owner sees their assigned CAPA items.
3. The Owner opens a CAPA Detail Drawer.
4. The Owner updates progress, links evidence, and submits for review.

## Journey 5: Export blocker resolution
1. User visits the **Readiness** page and sees a CAPA blocker.
2. The user opens the CAPA directly from the readiness blocker list.
3. The user (if approver) closes the CAPA after verification.
4. The readiness/export blocker disappears.
5. Final ZIP export becomes available (if no other blockers exist).
